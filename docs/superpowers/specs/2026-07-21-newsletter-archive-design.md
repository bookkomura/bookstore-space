# 小村碎碎念設計

## 目標

把寄至 Gmail 的小村碎碎念自動發布為書店空間裡可翻閱的電子報檔案室。玩家在左上樓梯口的「後頭村」互動點開啟檔案室後，可從最新一期開始，向回閱讀所有已同步的信件。

本功能處理寄件者 `info.rewildesign@gmail.com`、主旨含「小村碎碎念」的信件。符合條件的新信不經人工審核，成功解析後立即公開；「立即」表示同步與發布會立刻開始，網站會在該次自動部署完成後顯示新一期。

## 體驗設計

### 場景互動點

樓梯口新增一個固定的 `archive` 互動區，名稱為「小村碎碎念」。它位於左上樓梯右側的可行走空間，不覆蓋樓梯碰撞區或既有書櫃、展示櫃、櫃台互動區。互動標記沿用既有的靠近啟用／點擊開啟行為。

這個位置把每封信延伸為通往二樓展覽與「後頭村」的入口，而不是與中央長桌的選書內容或櫃台資訊競爭注意力。

### 檔案室閱讀器

檔案室是全螢幕 overlay，採兩個彼此獨立的捲動區：

1. 頂端為固定高度的信封期數列，依寄送時間由新到舊排列。它只可橫向捲動，每個期數是一個合起的信封。
2. 目前選取的一期顯示為掀開封口的信封，並在下方載入同一期的內容；切換信封後，內容捲動位置重設至開頭。
3. 下方是獨立的縱向信紙閱讀區，保留原信的段落、內嵌圖片與圖片說明的順序。此區可上下捲動，頂端信封列不會移動。
4. 活動、會員與社群連結以明確的外開卡片／按鈕呈現，保留原始 URL，於新分頁開啟並使用 `rel="noopener"`。

桌機以滑鼠、觸控板、鍵盤操作；手機以橫滑信封與縱滑內容為主。期數按鈕、外部連結、關閉控制都保持鍵盤可及、可見焦點與足夠觸控目標。使用者偏好減少動態時，信封封口不播放掀開動畫。

## 內容模型與建置輸出

Storyblok 新增一種 `newsletter` story/component。每一期包含：

- `sourceMessageId`：Gmail Message-ID，只供同步服務去重，不對前端輸出。
- `sentAt`：原信寄送時間；同時作為顯示日期與排序鍵。
- `subject`：原信完整主旨；閱讀器以第一個 `～` 後的文字作為標題，若沒有 `～` 則顯示完整主旨。
- `blocks`：依原信順序的正規化區塊；允許文字段落、圖片（含說明文字）、HTTPS 外部連結與分隔線。所有原信超連結均保留為外開連結卡，不依賴不穩定的「活動」自動分類。

現有 `ContentBundle` 新增 `newsletters` 陣列。內容抓取與驗證腳本會讀取已發布的 newsletter stories，依 `sentAt` 由新到舊排序，並產生靜態網站需要的內容 JSON。舊有 showcase、shelf 與店家資訊模型不改變。

## 自動發布架構

```text
Gmail push notification
  → Cloud Pub/Sub
  → 同步服務
  → Storyblok Management API + Asset Manager
  → Cloudflare Pages deploy hook
  → 書店靜態網站更新
```

1. Gmail watch 監聽指定帳戶的 Inbox 變化；同步服務每天續期 watch。
2. Cloud Pub/Sub 對同步服務發送推送通知。服務驗證推送身分、從 Gmail History API 取得新增信件，並以寄件者和主旨篩選。
3. 同步服務取得完整 MIME 訊息，依 HTML／純文字的可讀順序建立區塊，將 CID 內嵌圖片上傳到 Storyblok Asset Manager，將內容與圖片 URL 建立為已發布的 newsletter story。
4. 成功發布後，服務呼叫既有 Cloudflare Pages deploy hook；建置工作抓取已發布內容並輸出新的靜態檔。

服務持久化 Gmail history cursor、watch 到期時間、每封信的 Message-ID 與同步狀態，以處理通知重送、服務重啟與重試。這些狀態不進入前端內容檔。

## 安全與失敗處理

- Gmail OAuth refresh token、Pub/Sub 驗證設定、Storyblok Management API token 與 deploy hook 只存在同步服務的私密環境變數；不得放入 Vite 前端、內容 JSON 或 git。
- 同步服務只接受可驗證的 Pub/Sub 推送，並只發布完全符合寄件者與主旨規則的信。
- Message-ID 是唯一鍵；同一封信被重送或重試不會建立重複期數。
- 圖片上傳、內容驗證或 Storyblok 發布任一環節失敗時，該期維持未發布狀態並記錄可重試錯誤，不得暴露半篇電子報。
- 無可讀正文、無法解析 MIME、或 URL 不是 HTTPS 的信件不公開；圖片沒有來源替代文字時使用相鄰說明文字，兩者都缺少時使用「小村碎碎念圖片」。既有成功發布的檔案與網站版本不受影響。
- 最新部署成功前，使用者繼續看到上一個完整的靜態網站版本。

## 驗證策略

### 單元與內容管線

- MIME fixture 解析出段落、CID 圖片、圖片說明及所有外部連結，並維持原始順序。
- 不符合寄件者或主旨的信件不會產生 newsletter。
- 同一 Message-ID 重複處理只會建立一篇 story。
- 缺少正文、圖片上傳失敗、Storyblok 發布失敗各自不產生公開期數，並可進入重試。
- Newsletter schema 拒絕不安全 URL 與空白必要欄位；輸出結果按 `sentAt` 由新到舊排列。

### 元件與整合

- archive zone 開啟正確的 overlay；關閉後釋放場景控制權。
- 信封列按日期新到舊渲染，選取狀態只存在一封，切換後內容回到頂端。
- 頂端列維持固定，內容面板獨立縱向捲動；桌機與手機都不出現意外的整頁捲動。
- 圖片含可用替代文字與錯誤狀態；每個外部活動連結保留 URL、新分頁行為與安全關係。
- Playwright 覆蓋桌機鍵盤流程與手機橫滑／縱滑流程；production build、內容驗證與既有測試維持通過。

## 非目標

- 不匯入非「小村碎碎念」的 Gmail 郵件，不提供一般電子郵件瀏覽器。
- 不在本功能中加入人工審稿、帳號登入、多人編輯、站內報名或購物。
- 不更換既有場景圖片、角色控制、展示櫃、書櫃或店家資訊的互動設計。
