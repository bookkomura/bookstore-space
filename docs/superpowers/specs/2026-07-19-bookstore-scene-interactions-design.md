# 書店圖片場景與互動控制改版 — 設計規格

日期：2026-07-19
狀態：已與 Pai 完成 brainstorming 逐段確認，待書面規格審閱

## 1. 背景與目標

現有第一階段已具備 Phaser 3 場景、Vue 3 資訊視窗、Storyblok 內容模型、鍵盤移動、手機虛擬搖桿與三種互動內容。本次改版以使用者提供的乾淨書店圖片 `2.png` 取代目前的示意 tilemap，讓實際遊戲配置忠實呈現參考書店。

改版目標：

- 以單張圖片作為唯一場景背景，保留其中的家具、光影與人物。
- 另外製作一名可移動玩家，且美術風格必須與背景人物一致。
- 將圖片中的人物視為靜態 NPC；只有右側書店店員對應營業資訊。
- 提供五個商品展示區、中央店長選書區及右側營業資訊區。
- 所有可互動區平時顯示白底灰字驚嘆號；靠近後顯示內容名稱。
- 手機左側使用虛擬搖桿，右側新增只在可互動時亮起的點擊按鈕。

本次不做：

- 拆分或重建整套 tilemap。
- 搬動圖片中的家具或 NPC。
- NPC 動畫、對話或額外互動。
- 多房間、多人連線、聊天、帳號、購買或新後台。

## 2. 已選方案與取捨

採用「單張背景＋透明碰撞／互動圖層」。

背景圖片直接承擔完整美術呈現；Phaser 在其上疊加玩家、碰撞體、互動範圍、驚嘆號與名稱標籤。這個方案能最忠實保留原圖，也能沿用現有內容和視窗架構。

未採用的方案：

- **背景＋前景遮罩分層**：能產生更細緻的前後遮擋，但必須裁切家具並補畫被遮住的背景，容易出現接縫。
- **重新製作 tilemap**：最容易日後移動家具或增加動畫，但原圖沒有分層素材；必須重畫地板、家具背面、陰影和 NPC 動畫，成本遠超本次固定場景需求。

單張背景無法讓玩家自然穿過家具前後層，因此以精準碰撞體阻止玩家進入家具和 NPC 的圖像範圍，避免明顯的深度穿幫。

## 3. 世界與鏡頭

### 3.1 背景

- 使用乾淨原圖作為遊戲世界的固定背景；來源檔實際尺寸為 1572×1001、約 1.9 MB，必須維持此原始比例，不得拉伸。
- 房間外框為鏡頭和物理世界邊界，不允許玩家走入圖片外。
- 部署版可以使用視覺無明顯差異的壓縮格式降低手機下載量，但須保留原始圖片作為美術來源。
- 背景不可包含測試用標記、紅色手寫文字或互動提示；所有提示均由遊戲動態繪製。

### 3.2 玩家出生與鏡頭

- 玩家出生在左上入口／樓梯附近的可行走地面。
- 手機採局部放大鏡頭並跟隨玩家，優先維持玩家、NPC 和驚嘆號的清晰度。
- 桌機依視窗尺寸調整縮放；不可扭曲背景，也不可露出圖片世界以外的區域。
- 直橫螢幕切換時重新計算鏡頭縮放和控制元件位置，但保留玩家位置、目前靠近區域及已開啟內容。
- 鏡頭不得越過世界邊界；玩家接近牆邊時，角色可以偏離畫面中心以避免顯示世界外部。

## 4. 玩家美術

玩家不是背景圖片的一部分，也不得沿用目前的簡易佔位素材。

### 4.1 外觀

- 新設計一名訪客角色：深色頭髮、簡單外套、小背包。
- 角色須與背景 NPC 採相同的頭身比例、像素密度、深色輪廓、低飽和配色與暖色環境光。
- 原生顯示尺寸應接近背景中的成人 NPC；實際製作時以並排視覺比對為準，不可讓玩家顯得像不同解析度的貼圖。
- 玩家應容易從靜態 NPC 中辨識，但不能依靠不相容的高飽和色或不同畫風達成。

### 4.2 動畫與物理

- 提供上、下、左、右四方向。
- 每個方向包含待機狀態和循環走路動畫。
- 停止輸入時停在對應方向的待機影格；移動時播放該方向走路動畫。
- 物理碰撞範圍只包覆腳部附近，而不是整張角色圖片，使玩家能自然靠近桌面、書櫃和互動點。
- 開啟資訊視窗時立即停止速度和走路動畫；關閉後才恢復輸入。

## 5. 靜態 NPC 與碰撞配置

圖片內所有人物都保留為背景的一部分。

- 除右側書店店員外，其他人物不顯示驚嘆號、不開啟內容，也不回應點擊。
- 所有人物都視為不可穿越的靜態障礙。
- 外牆、上方書櫃、中央長桌與座椅、下方三組桌椅、左右書櫃、右側櫃檯及其他大型家具都需要透明碰撞體。
- 沿用 Phaser Arcade Physics，以多個矩形靜態碰撞體近似圖片輪廓，不為本次功能更換物理引擎。
- 碰撞體需保留足夠通道，玩家必須能從左上入口走到七個互動點。
- 碰撞體只負責阻擋玩家，不渲染於正式畫面；開發模式可選擇顯示邊界以校準。

## 6. 互動點配置

場景共包含七個互動點。

| ID | 類型 | 圖片位置 | 顯示名稱來源 |
|---|---|---|---|
| `showcase-1` | 商品 | 上方展示櫃最右側 | 對應 `Showcase.title` |
| `showcase-2` | 商品 | `showcase-1` 左側 | 對應 `Showcase.title` |
| `showcase-3` | 商品 | `showcase-2` 左側 | 對應 `Showcase.title` |
| `showcase-4` | 商品 | `showcase-3` 左側 | 對應 `Showcase.title` |
| `showcase-5` | 商品 | 五區最左側 | 對應 `Showcase.title` |
| `shelf-1` | 店長選書 | 中央長桌 | 對應 `Shelf.title` |
| `info-1` | 營業資訊 | 右側櫃檯內的書店店員 | 固定為「營業資訊」 |

互動範圍放在對應家具或 NPC 前方的可行走地面，不得要求玩家進入碰撞體。中央長桌可以有較寬的接近範圍，但整個範圍只對應同一個 `shelf-1`。

五個商品區彼此相鄰。若玩家同時落在多個範圍內，以玩家腳部中心到互動錨點距離最近者為唯一目前互動點；一次只能啟用一個名稱和一個內容。

## 7. 驚嘆號與名稱標籤

### 7.1 遠距狀態

- 七個互動點始終顯示驚嘆號，增加可發現性。
- 驚嘆號使用白色圓形背景、中深灰色字元、細灰框和柔和陰影。
- 標記必須在深色書櫃、木質家具及淺灰地板上都清晰可見。
- 遠距狀態只顯示驚嘆號，不顯示名稱。

### 7.2 靠近狀態

- 玩家進入互動範圍後，驚嘆號輕微放大並顯示柔和白色外光，不改為黃色。
- 驚嘆號旁展開白底深灰字名稱標籤。
- 商品名稱與店長選書名稱直接讀取本次已驗證的 CMS 內容。
- 標籤設定最大寬度和最多兩行；過長文字在第二行末尾截斷，但資訊視窗仍顯示完整標題。
- 玩家離開範圍後，名稱收合、驚嘆號回到遠距狀態。

## 8. 操作方式

### 8.1 手機與觸控裝置

- 左下顯示現有虛擬搖桿。
- 右下新增圓形「點擊」按鈕。
- 未靠近互動點時，右側按鈕維持可見但呈停用狀態，按下不觸發內容。
- 靠近互動點時，按鈕以明顯的亮色、外框或光暈進入啟用狀態。
- 按下啟用按鈕後，開啟目前唯一互動點的內容。
- 搖桿與點擊按鈕使用獨立觸控區，支援左手持續按住搖桿、右手同時點擊。
- 資訊視窗開啟時，兩個遊戲控制元件停用，避免背景誤操作。

### 8.2 桌機

- 不顯示虛擬搖桿與右側點擊按鈕。
- 保留方向鍵移動與 `E` 互動。
- 使用者也能用滑鼠直接點擊驚嘆號或已展開的名稱標籤。
- 點擊未靠近的遠處驚嘆號不開啟內容，避免繞過走近探索的核心互動。

## 9. 元件與資料流

維持「Phaser 管世界、Vue 管介面」的現有架構。

1. Vue 在建立 Phaser 遊戲前載入並驗證 `ContentBundle`。
2. Vue 根據內容建立互動名稱對照：五個 `Showcase.title`、一個 `Shelf.title` 和固定的「營業資訊」。
3. Phaser 載入背景、玩家 sprite、碰撞設定和七個互動區，並取得名稱對照。
4. Phaser 每幀以玩家腳部位置找出最近的有效互動區。
5. 目前互動區改變時，Phaser 經 `EventBridge` 發出進入／離開事件；Vue 依此啟用或停用手機點擊按鈕。
6. 手機按鈕、鍵盤 `E` 或鄰近標記點擊都要求 Phaser 觸發目前互動區。
7. Phaser 發出既有 `interact` 事件；Vue 依 `id` 和 `type` 開啟 `BookViewer`、`ShelfPanel` 或 `StoreInfoCard`。
8. Vue 開啟介面時發出 `ui:opened`，Phaser 凍結玩家；關閉時發出 `ui:closed` 並恢復控制。

不得建立第二套平行內容狀態。CMS 內容、Phaser 目前區域與 Vue 開啟視窗各有單一責任，並只透過已定義事件交換狀態。

## 10. 內容模型與驗證

現有 CMS 模型維持不變，但範例內容和部署內容必須擴充至五個商品：

- `showcases` 必須包含且只允許一個 `showcase-1` 至 `showcase-5`。
- `shelves` 必須包含對應中央桌的 `shelf-1`。
- `storeInfo` 維持單例，對應地圖中的 `info-1`。
- 商品和書單的 `title` 必須為非空字串。
- 每個地圖互動 ID 必須能找到對應 CMS 內容；CMS 中也不得存在本場景沒有的展示或書單 ID。
- 驗證失敗時中止建置，錯誤訊息列出缺少、重複或多出的 ID。

互動名稱不得另外手動寫死在場景設定中，以免後台標題和場景標籤不同步；唯一例外是使用者已指定固定文字的「營業資訊」。

## 11. 錯誤處理

| 情境 | 處理 |
|---|---|
| 背景或玩家素材載入失敗 | 顯示中文載入錯誤畫面，不啟動可操作的空白場景 |
| 互動 ID 與 CMS 不一致 | 建置失敗並列出差異 |
| 標題過長 | 靠近標籤最多兩行並截斷；內容視窗顯示完整標題 |
| 多個範圍重疊 | 只選玩家腳部中心最近的互動錨點 |
| UI 開啟時仍有觸控輸入 | 清除移動向量並停用左右控制 |
| 裝置旋轉 | 重新配置鏡頭和控制位置，保留玩家與 UI 狀態 |
| 商品圖片載入失敗 | 沿用既有佔位圖與重試按鈕 |
| 選填創作者連結為空 | 沿用既有規則，不渲染連結 |

## 12. 測試策略

### 12.1 單元與元件測試

- 解析背景場景設定後得到完整七個互動點。
- 驗證五個商品的左右順序：最右為 `showcase-1`，最左為 `showcase-5`。
- 驗證所有必要內容 ID、重複 ID和多餘 ID的錯誤。
- 驗證 CMS 名稱對照正確產生，營業資訊使用固定文字。
- 驗證重疊互動範圍選擇最近錨點，距離相同時使用穩定的設定順序。
- 驗證進入、切換和離開互動區的事件序列。
- 驗證觸控按鈕停用／啟用狀態及按下後的互動事件。
- 驗證資訊視窗開關會凍結／恢復玩家。
- 驗證四方向移動選擇正確動畫，停止時回到對應待機影格。
- 驗證裝置旋轉後不重置玩家和目前互動狀態。

### 12.2 E2E

- 桌機：從入口移動到商品區，使用 `E` 開啟內容，關閉後繼續移動。
- 桌機：只有靠近標記時，滑鼠點擊才可開啟內容。
- 手機 viewport：左下搖桿與右下點擊按鈕同時存在，區域外停用、區域內啟用。
- 逐一觸發五個商品、中央書單和營業資訊，確認開啟正確 Vue 元件與標題。
- 資訊視窗開啟期間，持續輸入不改變玩家位置。

### 12.3 真機與視覺驗收

- iOS Safari 與 Android Chrome 實測左手搖桿＋右手互動鍵的多點觸控。
- 直向和橫向旋轉後，背景不拉伸、不露出世界外區域，控制元件不遮住內容。
- 從入口可走到七個互動點，且不能穿越牆壁、家具、櫃檯或 NPC。
- 白底灰字驚嘆號在深色和淺色區域皆有足夠辨識度。
- 玩家與背景 NPC 並排檢查比例、像素密度、輪廓、色調和光影；任一項明顯不一致即不通過。
- 四方向待機和走路動畫無跳格、滑步或錯誤朝向。
- 背景在目標手機網路環境的載入時間可接受，壓縮版本無肉眼可見的破圖或嚴重色帶。

## 13. 完成條件

只有同時符合以下條件才視為完成：

1. 正式場景使用乾淨書店圖片，不再顯示示意 tilemap。
2. 玩家美術與背景一致，具備四方向待機和走路動畫。
3. 玩家從左上入口出生，鏡頭和碰撞在桌機與手機正常。
4. 七個互動點位置、編號、名稱及內容全部正確。
5. 驚嘆號為白底灰字，遠距可見，靠近後展開正確名稱。
6. 手機右側點擊按鈕只在互動範圍內啟用，且能與左側搖桿同時操作。
7. 桌機方向鍵、`E` 和鄰近標記點擊正常。
8. 自動測試、瀏覽器 E2E、實體手機和視覺驗收全部通過。
