# 中央方桌詩集上傳互動 — 設計規格

日期：2026-07-29
狀態：已與 Pai 完成設計確認，待書面審閱

## 1. 目標與範圍

在書局場景的中央方桌新增「詩集上傳」互動點。訪客靠近、使用既有互動操作後，於書局頁面內開啟覆蓋全螢幕的詩集上傳網站：

`https://paiwh-poem-display.hf.space/`

訪客可直接在此介面使用該網站既有的詩集上傳功能；關閉介面後回到原本的書局場景與玩家位置。

本次不做：

- 不修改詩集網站的內容、上傳流程或資料儲存。
- 不另開瀏覽器分頁或視窗。
- 不變更既有中央長桌的「店長選書」互動。
- 不新增 CMS／Storyblok 欄位或後台設定。

## 2. 採用方案

採用「新增靜態互動區＋Vue 全螢幕 iframe 覆蓋層」。

- 新增固定 `poem-upload-1` 互動區，位置放在中央方桌的可行走側邊，與桌面碰撞區分離；場景顯示名稱為「拾字成詩」。
- 加入新的 `poemUpload` 互動類型；Phaser 和既有 `EventBridge` 仍只負責偵測與派送互動事件，Vue 負責開關介面。
- 新增 `PoemUploadOverlay` 元件，以全螢幕、無沙箱限制的 iframe 載入指定網址，讓檔案選取與上傳保有網站原生行為。
- 覆蓋層只提供清楚的「關閉」控制；不提供另開分頁按鈕。

這個方案沿用「Phaser 管世界、Vue 管介面」的既有邊界，並且不會侵入第三方網站的上傳程式。

## 3. 互動與資料流

1. `sceneLayout` 將 `poem-upload-1` 與其他靜態互動點一併建立，錨點位於中央方桌旁可抵達的位置。
2. `interactionLabels` 為此固定互動點提供「拾字成詩」名稱。
3. 玩家進入範圍後，沿用既有驚嘆號、名稱標籤、鍵盤 `E`、點擊標記與手機互動按鈕。
4. Phaser 發出 `{ id: 'poem-upload-1', type: 'poemUpload' }`；Vue 設定 `showPoemUpload`，並發出 `ui:opened` 凍結場景控制。
5. `PoemUploadOverlay` 以 iframe 全螢幕顯示詩集網站。iframe 不使用 `sandbox` 屬性，避免額外阻礙其上傳功能。
6. 使用者點擊關閉鍵或按 `Escape` 時，Vue 卸載覆蓋層、發出 `ui:closed`，使用者可從原地繼續移動。

## 4. 介面、可近用性與錯誤處理

- 覆蓋層填滿 viewport，iframe 可用整個可視空間；關閉鍵維持在父頁最上層，鍵盤可聚焦且帶有中文可存取名稱。
- 開啟時背景遊戲輸入必須停止，避免 iframe 操作傳遞為角色移動；關閉後才恢復。
- iframe 加上描述性 `title`，讓輔助技術識別其用途。
- 若第三方網站未能載入，瀏覽器仍顯示該來源的原生錯誤狀態；書局不可當作成功上傳或存取其檔案資料。
- 該網站目前未回傳禁止 iframe 嵌入的 `X-Frame-Options` 或 CSP 標頭。未來若第三方服務變更政策，應在實機驗收中發現並另行決定替代方案。

## 5. 測試與完成條件

### 自動測試

- 互動區建置結果包含唯一的 `poem-upload-1`，類型與中央方桌的位置正確。
- 互動名稱對照包含固定文字「拾字成詩」。
- 從 `poemUpload` 互動事件開啟覆蓋層，並傳入正確的 iframe URL。
- 覆蓋層的關閉鍵與 `Escape` 都會卸載介面並送出既有 UI 關閉流程。
- 覆蓋層開啟期間，Phaser 場景維持暫停輸入。

### 瀏覽器驗收

- 桌機可從入口抵達中央方桌的詩集上傳互動點，並以 `E` 開啟全螢幕覆蓋層。
- 手機可由既有互動按鈕開啟，iframe 在直向與橫向皆完整覆蓋可視區域。
- 在覆蓋層中可選擇檔案並送出至外部詩集網站；此項須以實際部署環境手動驗收。
- 關閉後回到書局，玩家位置不變且可再次操作。

完成時，使用者能在中央方桌直接進入並使用詩集網站的上傳功能，過程不會開啟新的瀏覽器分頁或視窗。
